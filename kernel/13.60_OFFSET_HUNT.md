# 13.60 kernel-offset hunt — results (Oct 12, agent 1 of 3)

Disassembly of the dumped 13.60 kernel `.text` (ktext_0.bin / ktext_2800000.bin).

**Text base CONFIRMED**: `0xffffffff80200000` = file offset 0 of `ktext_0.bin`
(via rodata string-pointer arithmetic: pointer `0xffffffff823f9240` in kdata_1360 resolves
to the `msg_vc_startup_4` string at ktext_0 file offset `0x21f9240`).

## Blocked — not in the dumps
- **`acpi_sleep_machdep`** — the acpi.c sleep-path strings are in `kdata_1360.bin`
  (`AcpiEnterSleepState failed - err = %d` @0x6eec76, `acpi_wakeup: failed to resume` @0x6eec9d,
  `__FILE__` `W:/Build/J03950001/.../acpi.c` @0x6c2227), but the referencing code is in a
  **scrambled region** of `ktext_0.bin` — no RIP-relative xref reachable.
- **`ACPIGBL_FACS`** — the `AcpiSetFirmwareWakingVector` write pattern (FACS+0x18/+0xc) is
  absent from clean text; ACPICA code is in a scrambled region.
- **`IDT` / `COMMON_TSS`** — live in the kernel `.bss` at image offset ~`0x3ac0000-0x3b00000`,
  which is the **un-dumped gap** between `ktext_2800000.bin` (ends `0x3a00000`) and
  `ktext_5ea0000.bin` (starts `0x5ea0000`).
- **`vmmcall`** — the opcode `0f 01 d9` appears **0 times** in `ktext_0.bin` (only a false
  positive in scrambled data in ktext_2800000). The hypercall wrapper is in a scrambled region
  or uses a non-standard mechanism.
- **`pcpus[]` base** — NOT present (high confidence). It is the *inner hypervisor's* structure,
  not a kernel symbol; the kernel dumps contain only the FreeBSD guest. Needs an HV memory dump.

## Consequence
The kernel-text dump is **partial**: a ~2.8 MB scrambled header (0x0-0x2b400f) plus interleaved
scrambled regions plus the `.bss` gap 0x3a00000-0x5ea0000. The timing/global offsets
(`acpi_sleep_machdep`, `ACPIGBL_FACS`, `IDT`, `COMMON_TSS`) and the hypercall wrapper all fall
in those missing regions. **Next: re-dump those regions from the console** (the GPU-DMA XOM
bypass again, covering the header + the .bss gap).


## Consolidated (agents 2 & 3, Oct 12)

- **`.data` base = text + `0xCC0000`** (CORRECTED — from WAK1360-Relapse `OFFSET_KERNEL_DATA`).
  The earlier `0x82000000` conclusion (agent 2's string-xref) was wrong. `sysent[]` at kdata
  offset `0x38` (24-byte stride), `sy_call[0]=0xffffffff804772b8`.
- **Gadgets refined** (agent 2): `mov [rdi],rsi;pop rbp;ret` has 3 clean setter sites
  (`0x19260c4`, `0x1926164`, `0x1f682e4`). `pop rdi` primary `0x4bd6c2`, `pop rsi`
  `0x6d14b0`, `pop rdx` `0x12109bd`, `pop rcx` `0x1ea585d`, `pop rax` `0x8fc3e8`, `pop rsp`
  `0x611599`, `iretq` `0x408f38`. **`wrmsr;ret` ABSENT** (no real wrmsr site). **`vmmcall`
  ABSENT** (confirmed). `add rsp,0x28;pop rbp;ret` absent — substitute
  `add rsp,0x28;pop rbx;pop rbp;ret` (`0x4b419c`) or `add rsp,0x20;pop rbp;ret` (`0x4b8eca`).
- **XOM scrambling is extensive** — scattered ciphertext regions throughout the text, not just
  the 2.8 MB header. That (plus the .bss gap 0x3a00000-0x5ea0000) is why the timing/global
  offsets cannot be xref-resolved from this dump.
- **`IDT` / `COMMON_TSS` NOT-PRESENT** (in .bss >= 0xffffffff82f00000; `lidt`/`ltr`/`setidt`
  code is scrambled). **`ACPIGBL_FACS` CANDIDATE** — the ACPI table-descriptor region is at
  kdata `0x1c6ac0` (`"FADT"` array + slid KVAs), but the single `AcpiGbl_FACS` field not
  isolated (its only writer, `AcpiSetFirmwareWakingVector`, is in scrambled text).
- **`pcpus[]` NOT-PRESENT** (both agents, high confidence): it is the hypervisor's own array
  in the SME carve-out (0x60000000-0x70000000), not guest kernel memory.

## What's needed next
Re-dump the **scrambled text regions** + the **.bss gap (0x3a00000-0x5ea0000)** from the
console (the GPU-DMA XOM bypass left them ciphertext). That unlocks `acpi_sleep_machdep`,
`ACPIGBL_FACS` (via its scrambled writer), `IDT`/`COMMON_TSS`, and the `vmmcall` hypercall
wrapper. `pcpus[]` still needs an HV dump (SME carve-out).
